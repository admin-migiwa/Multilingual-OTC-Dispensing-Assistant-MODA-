## 目的と背景

MODA は、言葉が通じないせいで外国人の患者さんに市販薬を売れない状況をなくすための、店頭用アプリ。

- **誰の**：外国人の患者さん（旅行者・在留外国人）と、店頭で対応する薬剤師
- **どの課題を**：言葉が通じないため、聞き取り・説明・理解の確認が不十分になり、販売できなかったり、時間がかかったりする（最優先の課題）
- **どう解決するか**：店頭の iPad 1台で、母国語の問診から販売記録までを決まった順番で進める。AI は問診と翻訳を手伝うだけで、判断はすべて薬剤師が行う

**きっかけ**：最初は、薬局から紹介するオンライン診療の煩雑な手順を楽にする連携アプリを検討していた。その後、海外の方からのオンライン診療の依頼や、海外の方が薬を希望されたときの対応に改善点が見えてきたため、外国人対応に方向を変えた。

## ハッカソン提出版（11月8日20時締め切り）

締め切りまでに作るのは、試験運用版のすべてではない。「言葉の壁が消えて、安全に薬を売れる」流れを1本だけ作り、3分の動画で見せられるようにする。架空のデータだけを使い、公開リポジトリとして提出する。

- **テーマとの対応**：中心はテーマ2「本来、誰にでも届くべきものを」（言語の壁）。出発点はテーマ1（薬剤師として現場で気づいた不足）
- **提出物**：プロジェクト概要、3分のデモ動画、公開 GitHub リポジトリ
- **扱う薬**：区分ごとに1品目ずつ（8品目）。すべて架空の薬で、区分・手順の組み合わせは docs/demo-drugs.md の実在品にならう。ほかに、NSAID系を含まない解熱鎮痛薬1品目と、解熱鎮痛成分を含まない漢方1品目（ぜんそく歴がある・わからない人の代わりの候補用、11/4 追加）、架空の取扱外の薬3品目。全区分の手順を動かして見せる（docs/demo-data/drugs.md）
- **言語**：9言語。動画では2〜3言語を見せる
- **AI 翻訳は中心機能**：患者さんの文を日本語に、薬剤師の文を母国語に訳す。薬剤師の画面には、訳した文を日本語に訳し戻したものも並べて表示し、薬剤師が訳の正しさを確かめられるようにする

**デモで見せる流れ**

1. 患者さんが母国語を選ぶ
2. 希望の薬を伝える：商品名や成分名を入力するか、スマホの画面や実物を撮影する。希望の薬がなければ症状から探す
3. 体の状態や症状に、母国語で1問ずつ答える
4. 緊急症状があれば、問診をその場で止め、薬剤師が根拠を確認して119番と受診を案内する
5. 薬剤師の画面に、日本語のまとめ、候補の薬、禁忌の判定、区分ごとのチェックリストを表示する（候補は薬剤師にだけ見せる）
6. 薬剤師が PIN で承認する。市販薬では対応できなければ、受診を勧める案内を出す
7. 母国語の説明書（原文も併記）を表示・印刷し、理解したかを確認する
8. 患者さんに評価してもらい、販売記録を残す

**ハッカソン版に入れないもの**（概要では「今後の計画」として紹介）：管理画面と添付文書 PDF の取り込み（薬は開発側で登録）、音声、母国の処方箋や母国の薬の箱の読み取り、口コミの案内、病院の登録（受診案内は固定の文だけ）、ログインや店舗ごとの分離、データベース、実際の患者データ。

## 利用者と提供先

ハッカソンの後、勤務先の会社の薬局2店舗で試験運用する。その後、他社の薬局やドラッグストアにも使ってもらう想定。最初の営業先は個人・中小の薬局の見込みで、提供元はまだ決まっていない。

| 立場 | 役割 |
| --- | --- |
| 企画者 | 薬局薬剤師。試験運用の店舗側と、将来の提供元を兼ねる |
| 患者さん | 外国人旅行者・在留外国人。iPad で母国語を選び、問診に答える |
| 薬剤師 | 問診の内容を確認し、薬を決め、承認と服薬指導を行う |
| 店舗スタッフ | 最初の案内と会計。多言語に対応できるスタッフはいない |
| 店舗管理者・本部管理者 | 取扱薬・記録・アカウントの管理（外部提供を見据えて最初から用意） |
| 外部提供先（将来） | 外国人対応に慣れていない個人・中小の薬局 |

## 成功の基準と測り方

試験運用でいちばん大事なのは「やり取りに齟齬や不足がないこと」。外にアピールしにくいため、接客時間と販売件数も一緒に測る。

| 測るもの | 測り方 | 何と比べるか |
| --- | --- | --- |
| 患者さんの理解・満足 | 最後の画面で、母国語の簡単な評価（例：「説明は分かりましたか」を3段階） | 試験運用中の推移 |
| 薬剤師から見た齟齬 | 接客後に1タップで記録（例：「伝わらない場面があったか」） | 試験運用中の推移 |
| 1件の接客時間 | アプリが開始から完了までを自動で記録 | 導入前の実測値 |
| 販売件数・断った件数 | 販売記録と「販売しなかった記録」を集計 | 導入前の実測値 |

導入前の計測が必要。現在は時間を測っておらず、聞き取りやアンケートも一部のスタッフが非公式に行っているだけ。開発と並行して、紙の記録表などで「外国人対応1件ごとの時間・販売できたか・困ったこと」を残し始める。

**口コミの誘導**：最後の画面に店舗の口コミページへの案内を置き、将来の来局につなげる案。計画には残すが、規約や広告ルールを確認するまで運用には入れない。

## 主な利用場面

店頭でもっとも多いのは、患者さんがスマホで日本の商品の画像やサイトのスクリーンショットを見せる場面。写真は iPad のカメラでスマホの画面を撮って取り込む。

| よくある順 | 場面 | アプリがすること |
| --- | --- | --- |
| 1 | 日本の商品の画像・サイトのスクショを見せる | 商品名を読み取り、取扱薬と照合する。店にない場合は、同じ成分・近い成分の取扱薬を候補として出す（最終的に決めるのは薬剤師） |
| 2 | 症状を伝えて薬を探す | 母国語で問診し、候補の薬を薬剤師に提案する |
| 3 | 母国の処方箋の写真を見せる | 成分を読み取り、市販薬で代わりになるかを示す。代わりがなければ受診を案内する |
| 4 | 母国の薬の箱・ラベルを見せる | 成分を読み取り、日本の取扱薬と照合する。含量の違いや注意が必要な成分を強調する |
| 随時 | 市販薬では対応できない（禁忌・症状が重い・処方薬が必要） | 受診を勧め、店舗が登録した近くの病院と、外国人向けの公的な医療機関検索ページの QR を表示する |
| 随時 | 緊急症状 | 問診をすぐに止め、薬剤師が根拠を確認したうえで、母国語で119番と救急受診を案内する（決まったこと #38） |

写真の読み取りの課題：スマホの画面を撮るため、反射やモアレで文字が読みにくくなることがある。読み取り結果は必ず候補として表示し、人が確認する。

## 試験運用版の範囲（ハッカソンの後）

日本の市販薬は、すべての区分を最初から扱う（あとから足すと作り直しになりやすいため）。海外の薬については網羅を目指さず、照合できる成分が少なくてもよい。

| 項目 | 試験運用での範囲 |
| --- | --- |
| 扱う区分 | 要指導（特定要指導・緊急避妊薬を含む）・第1類・指定第2類・第2類・第3類・指定濫用防止医薬品のすべて。品目数は取扱薬の一部（10〜20品目）から |
| 言語 | 9言語すべて（日本語・英語・中国語簡体・中国語繁体・韓国語・スペイン語・ポルトガル語・フランス語・ベトナム語） |
| 接客の流れ | 言語選択 → 問診 → 薬の選択 → 薬剤師の承認 → 説明書の印刷 → 服薬指導・理解の確認 → 販売記録 → 会計案内 |
| 写真鑑別 | 日本の商品の画像・スクショ（最優先）、持参された実物、バーコード、母国の処方箋、母国の薬の箱・ラベル。スマホの画像は iPad で画面を撮って取り込む。商品名・成分名の入力でも検索できる |
| 安全の仕組み | 禁忌の判定と薬剤師による解除、区分ごとの販売手順のチェック、緊急症状の検知と案内 |
| 受診案内 | 受診を勧める文＋店舗が手で登録した近くの病院（数件）＋公的な医療機関検索ページの QR。予約や連携はしない |
| 効果の測定 | 患者さんの評価、薬剤師の評価、接客時間の自動記録、販売しなかった記録 |
| 口コミの案内 | 計画のみ（運用には入れない） |
| 管理画面 | 店舗管理と本部管理（取扱薬・添付文書 PDF の取り込み・記録・アカウント） |
| 音声入力・読み上げ | 試験運用の途中から追加する。前半は文字とタップだけで運用し、前後で比べる |

**前半と後半に分ける**：前半は、ハッカソン版の流れに「日本の商品の画像の読み取り」を加えた内容で始める。母国の処方箋や母国の薬の読み取り、音声、本部管理画面は後半に足す。

**翻訳の方針（決定 #23。ハッカソン段階では外部確認をしない）**：どの薬にも共通する定型文の部品（緊急案内・注意文・用法用量の型）だけを、最初に1回だけ外部で人が確認する。薬を追加するときは部品を組み合わせるだけなので、新しい確認は発生しない。部品で表せない文章は AI 翻訳の「参考訳」として表示し、添付文書の原本も渡す。

## やらないこと

オンライン診療との連携は、外部提供には含めないほうがよいため、将来作るとしても別の機能として切り分ける。

| やらないこと | 理由・扱い |
| --- | --- |
| オンライン診療・病院との連携 | 将来の拡張。外部提供とは別の機能に分ける |
| 処方薬が必要な人の受診手配 | 受診の案内まで。予約や情報の受け渡しはしない |
| 地図 API で近くの病院を自動表示 | 将来の候補（費用が抑えられれば）。今回は店舗が手で登録する |
| 登録販売者による承認 | 承認は薬剤師だけ |
| 錠剤そのものの鑑別 | 文字が印刷されたものだけを読む |
| 海外医薬品の網羅 | 照合できる成分は少しずつ増やす |
| POS 連携 | 会計は案内だけ |
| 患者さんのスマホから写真を送ってもらう仕組み | iPad で画面を撮る方法に絞る |
| 第2弾の言語（ネパール語・タイ語など） | 言語選択の件数を見て判断する |
