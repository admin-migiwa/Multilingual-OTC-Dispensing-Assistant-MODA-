## 1. 概要

外国人の患者さんが母国語で市販薬を購入でき、薬剤師が薬機法上の手順を漏れなく守れるようにする店頭用 Web アプリ。
店頭の1台の iPad で、問診 → 薬の選択 → 薬剤師の承認 → 説明書の印刷 → 服薬指導 → 販売記録 までを完結させる。

- **利用者**：患者さん（外国人旅行者・在留外国人）、薬剤師、店舗スタッフ、本部管理者。将来は登録販売者（第2類・第3類）。
- **扱う医薬品**：要指導医薬品（特定要指導医薬品を含む）、第1類・指定第2類・第2類・第3類、指定濫用防止医薬品。
- **大前提**：AI は問診と翻訳の手伝い。薬の候補・禁忌の判定・服薬指導の文章はすべて薬剤師への提案で、最終判断は薬剤師。

## 2. 決定事項

## 3. 技術構成

| 領域 | 採用 | 補足 |
| --- | --- | --- |
| 構成 | TypeScript のモノレポ（pnpm） | `apps/web`、`packages/domain`（医療ルール）、`packages/i18n`（言語） |
| 画面・サーバー | Next.js（App Router）＋ Tailwind CSS | 画面と API を同じアプリに。Vercel の関数は東京リージョン |
| DB | Supabase（PostgreSQL、東京） | 行レベルのアクセス制御で店舗ごとに分離。リージョンは後から変えられない |
| 認証 | Supabase Auth ＋ 薬剤師の PIN | 端末ログインと、承認・禁忌解除時の PIN 再認証 |
| ファイル保存 | Supabase Storage | 添付文書 PDF、説明書、出力ファイル |
| 印刷 | 当面はブラウザで HTML を印刷（AirPrint） | サーバーでの PDF 保存が必要になればヘッドレス Chromium を追加 |
| AI | 開発中は仮の AI → ハッカソン版は Claude API（Claude Opus 5.5）→ 試験運用から Bedrock の国内推論 | 呼び出し口は1か所で、接続先は差し替えで切り替える。応答は必ず JSON スキーマで受け取り検証 |
| 翻訳 | 定型文は事前翻訳＋人の確認。自由入力のチャットだけ AI で翻訳 | 緊急案内など安全上重要な文言を毎回 AI に翻訳させない |
| 音声 | Azure AI Speech | 9言語と第2弾候補すべてに対応 |
| カメラ | JAN バーコードを端末内で読む（zxing）。読めないとき・お薬手帳は AI で読む | AI の読み取り結果は候補として出し、人が選ぶ |

全国展開に備えて最初から守ること：すべてのデータに本部・店舗の ID を持たせる／医療ルールは純粋な TypeScript、DB は素の PostgreSQL として使う／販売記録は版を重ねる／言語と販売手順はデータで一元管理する。

## 4. 健康情報と AI の扱い

- 保存は東京リージョン。保存時・通信時とも暗号化。
- AI に送るのは問診の本文と最小限の属性（性別・年齢など）だけ。連絡先・店舗名・薬剤師名・セッション ID は送らない。
- 氏名は取得しない。連絡先は任意。
- ログに問診の本文を出さない（マスクかハッシュ）。AI の入出力は監査に必要な範囲だけ残す。
- API キーはサーバーの環境変数だけ。ブラウザは自前の API だけを呼ぶ。
- 作業中の状態はサーバーに逐次保存し、端末にはセッションの参照だけを持つ（例外は通信障害時の緊急記録）。一定時間操作がなければ画面を自動でクリア。
- 開発中は架空のテストデータだけを使う。

## 6. 状態遷移と承認ゲート

実装：`packages/domain/src/session/state.ts`

```
言語選択 → 属性入力 → 問診 ─(緊急検知：どの状態からでも)→ 緊急終了［記録］
                        ↓ 必須項目がそろう
                    薬の選択 ⇄ 問診（チャットに戻る）
                        ↓
                    薬剤師の確認 ─→ 販売せず［理由を記録］
                        ↓ PIN で承認（区分ごとの手順がすべて完了していること）
                    承認［販売記録を作成］→ 服薬指導（印刷・指導・理解確認）→ 会計案内 → 完了
```

- 印刷・服薬指導・会計の API は、処理の最初に `assertActionAllowed()` を呼ぶ。
- DB 側でも、承認がなければ販売記録を作れない制約をかける。
- 理解の確認が済むまで会計に進めない。

## 7. 医療判断ロジック

すべて `packages/domain` に純粋関数として置き、外部サービスなしでテストする。テストケースは薬剤師が確認した表から作る。

### 問診の進め方とチェック

- 次に聞く項目はサーバーが決め、AI は言い回しと聞き取った内容の抽出だけを担当する。
- AI の出力は `{質問する項目, 質問文, 抽出した事実[], 緊急フラグ, 意味が通らない入力か}` の形に固定。
- サーバーは「質問が1項目だけか」「確認済みの項目を聞き直していないか」「値が許された範囲か」を検証。不合格なら1回だけ再生成し、それでもだめならエラーで止める。
- 一度に複数のことを答えたら、該当するすべての項目を確認済みにする。
- 男性には妊娠・授乳を聞かない（サーバー側で除外）。
- 意味の通らない入力には、推測で進めず直前の質問をもう一度聞く。「間違えました」には訂正を受け入れ、直前の回答をやり直すボタンも置く。
- 必要な項目がすべて確認できるまで問診を終えない。

### 緊急症状

激しい胸の痛み、突然の激しい頭痛、吐血・喀血、呼吸困難、意識の異常などを検知したら、問診をすぐに止め、薬剤師が根拠を確認したうえで、患者さんの言語で119番と救急受診を案内する（患者さんと薬剤師は一緒に端末を操作する前提。spec.md 決まったこと #38）。

- 検知は3層：AI の緊急フラグ、言語ごとの緊急キーワード辞書（サーバーと端末の両方）、画面の「緊急」ボタン。
- 案内画面と文言は端末に組み込み、通信が切れていても表示する。
- 記録は通常その場で保存。保存できないときは端末に暗号化して保管し、復旧後に送る（ハッカソン版では保留）。

### 禁忌の判定と解除

- 判定には、最初に入力した属性と問診で確定した事実の両方を使い、「禁忌」「注意」「問題なし」と理由を返す。
- 判定の軸：年齢制限、持病（緑内障・前立腺肥大・胃潰瘍・喘息など）、妊娠・授乳、アレルギー成分。運転予定があれば眠くなる薬に警告。
- 「禁忌」は既定で選べない。薬剤師が PIN で再認証し、理由を選んで解除できる。「聞き取りと違った」を選んだら、問診で確定した内容も訂正できる。
- 「注意」は薬剤師が確認したことを記録すれば進める。

### 区分ごとの販売手順

選んだ薬の組み合わせから必要な手順をすべて合わせた一覧を作り、未完了があれば承認できない。

| 区分 | 承認できる人 | 承認前に必要な手順 |
| --- | --- | --- |
| 要指導医薬品・第1類 | 薬剤師 | 書面での情報提供、理解の確認、法定項目の記録 |
| 特定要指導医薬品（緊急避妊薬など） | 薬剤師 | 上記に加え、別紙書類の確認と薬剤師の前での服用の確認 |
| 指定濫用防止医薬品 | 薬剤師（将来は登録販売者も区分に応じて） | 年齢、購入数量（大容量・複数個）、他店での購入状況、複数購入の理由、使用目的の確認。濫用の危険の書面での情報提供。18歳未満は別紙の氏名確認＋別紙番号 |
| 指定第2類 | 薬剤師（将来は登録販売者も） | 禁忌の確認と相談を促す表示 |
| 第2類・第3類 | 薬剤師（将来は登録販売者も） | 禁忌の確認 |

確認項目と数量基準は、法令・通知を確認して手順定義データの初版にする（未確定）。

### 添付文書の取り込みと服薬指導

- 添付文書は、AI が抽出した各項目に原文の引用を付けさせ、引用が PDF に実際にあるかをサーバーで照合する。そのうえで人が確認してから登録する。要約・省略しない。書かれていない禁忌や年齢制限を作らない。
- 年齢別の用法・用量の表は、患者さんの年齢に当たる部分だけを表示する。
- 服薬指導の文章は、注意事項を「この患者さんに当てはまる」「一般的な注意」「当てはまらない」にルールで振り分け、AI は言い回しだけを担当する。薬剤師が選び、修正して確定する。

## 8. 写真鑑別（海外医薬品を含む）

AI はパッケージの文字を読むだけで、成分の照合はアプリの成分辞書で行う。対象は文字が印刷された外箱やラベル。錠剤そのものの鑑別は対象外。

1. 撮影（日本の製品はまず JAN バーコードで探す）
2. 文字の読み取り（Bedrock）：製品名・有効成分と含量・剤形・表記言語を印字どおりに抽出。読んだ文字を添え、印字がない項目は「不明」
3. 人が確認：画像と抽出結果を並べ、薬剤師が成分を確定
4. 成分名をそろえる：成分辞書で各国の呼び名を同じ成分に寄せる（塩の違いも）
5. 未登録の成分は自動で候補を出す：AI が INN と日本語名の候補に変換し、同時に RxNorm と PubChem（米国の公的機関、無料・登録不要、送るのは成分名だけ）で検索。一致すれば「照合済みの候補」、しなければ「未確認」。日本で未承認の成分は警告。薬剤師が確定するまで照合・禁忌判定に使わない
6. 取扱薬との照合：「まったく同じ成分（あればそれだけ）」「同じ成分をすべて含む」「同系統の成分構成」「同系統の成分を含む」「同じ効き目の分類」の5段階（11/5 見直し）。配合剤のときは、患者さんの主訴を確認するよう薬剤師の画面に印を出す
7. 違いを強調：含量の違い、日本の市販薬にない成分、指定濫用防止医薬品の成分

**検索ショートカット**：識別した成分名を入れて指定サイトを開くボタン。URL に検索語を入れられないサイトは、成分名をコピーして検索画面を開く。サイトは管理画面で設定。初期設定：

- PMDA 一般用・要指導医薬品の添付文書等検索 https://www.pmda.go.jp/PmdaSearch/otcSearch/
- JSM-DB（日本語版） https://search.jsm-db.info/main2.php?uriflg=JSM
- JSM-DB（英語版） https://search.jsm-db.info/sp_en/index.php
- キュアベル https://curebell.jp/app

**成分辞書**：取扱薬の成分と、注意が必要な成分（指定濫用防止医薬品の対象成分：コデイン、ジヒドロコデイン、プソイドエフェドリン、エフェドリン、デキストロメトルファン、ジフェンヒドラミンなど／アレルギーの申告が多い成分：アスピリン、イブプロフェンなど）から始める。呼び名の情報源：日本語名・英語名は JAN データベース、中国語・フランス語・スペイン語は WHO の INN、米国名は RxNorm、ほかの言語は AI の下書きを薬剤師が確認。未登録の呼び名は管理画面に溜めて確認後に追加。

その他：お薬手帳は氏名部分を隠すか撮らない（写真は保存しない）。効き目の分類は自前で持つ（WHO の ATC は商用利用に制約）。精度は海外パッケージ約50点の試験セットで確認。

| 店舗管理画面 | 店舗管理者 | 問診履歴、販売記録の確認・修正・1件印刷・期間指定の一覧出力、禁忌解除の一覧、取扱薬と価格、店舗独自の薬、薬剤師と PIN、2年を過ぎた記録の削除承認、検索ショートカットの設定 |
| 本部管理画面 | 本部管理者 | 医薬品テンプレートマスタ、添付文書 PDF の取り込みと確認、翻訳の確認、成分辞書、店舗登録薬の取り込み、販売手順の定義、店舗アカウント |

リロードしても作業中の内容はサーバーから復元する。共用画面から薬剤師専用画面へ移るときは PIN を求める。

## 10. 使用する API

| サービス | 使う場面 | 段階 |
| --- | --- | --- |
| Supabase Auth / Database / Storage | ログイン、全データ、ファイル | 1〜 |
| Vercel Functions（東京）/ Cron Jobs | アプリの API、2年経過記録の削除候補の日次処理 | 1〜 / 7 |
| Amazon Bedrock Converse API（`jp.` 推論プロファイル） | 問診、翻訳、服薬指導の言い回し、画像・PDF の読み取り | 5〜 |
| Azure AI Speech | 音声認識・読み上げ | 6〜 |
| RxNorm API / PubChem API | 写真鑑別の未登録成分の自動検索（成分名だけを送る） | 8 |

端末のブラウザ機能：getUserMedia（カメラ・マイク、HTTPS のみ）、バーコード読み取り（zxing。iPad の Safari は標準機能が未対応）、MediaRecorder（録音して Azure に送る。ブラウザ標準の Web Speech API は使わない）、window.print（AirPrint）、Service Worker（緊急案内の保持）、IndexedDB ＋ Web Crypto（緊急記録の一時保管）。

## 12. 開発の段階と費用

1. **土台**：モノレポ、認証と役割、DB と監査ログ、エラーの扱い、言語の一元管理
2. **医療ルールとテスト**：禁忌判定、手順判定、問診の項目管理、緊急検知
3. **医薬品マスタ（手入力）＋成分辞書と照合処理**
4. **縦に一本通す**：仮の AI と定型の質問で、問診 → 選択 → 承認 → 販売記録 → 印刷 → 出力
5. **AI 問診**：応答の検証と補正、緊急検知、割り込み、やり直し。ここで Bedrock につなぐ
6. **服薬指導と説明書**：多言語の印刷、読み上げ、理解の確認
7. **管理画面と取り込み**：添付文書 PDF の取り込み、翻訳の確認、管理画面、出力
8. **カメラ（写真鑑別を含む）と音声入力**
9. **検証**：勤務先の2店舗での試験運用、薬剤師による安全レビュー、脆弱性の確認

| 段階 | AI | インフラ | 月額の目安 |
| --- | --- | --- | --- |
| 1〜4 | 仮の AI | Vercel Hobby、Supabase Free | 0円 |
| 5〜8 | Bedrock の国内推論（AWS 新規アカウントの無料クレジット） | 同上 | 実質0円 |
| 9〜 | Bedrock（会社名義） | Vercel Pro、Supabase Pro | 約1万2,000円（2店舗・月300件の試算） |
