# MODA（Multilingual OTC Dispensing Assistant）

> **言語の壁をなくす接客支援。AI は助言せず、訳して聞き取るだけ。薬の判断は薬剤師。**
>
> このリポジトリはハッカソン提出版です。**薬も患者さんも、すべて架空のデータ**です（薬の名前は「モダ〇〇（架空）」、成分は「架空成分 N1」など。[`docs/demo-data/`](docs/demo-data/README.md)）。

外国人の患者さんが母国語で市販薬を買えるようにし、薬剤師が薬機法の手順を漏れなく守れるようにする、店頭の iPad 用 Web アプリです。薬局薬剤師が企画しました。

## デモ

- **デモ動画**：（公開後にここへリンクを足します）
- **公開デモ**：URL と薬剤師用の PIN は、提出フォームの審査員用の欄に書いています。無料の公開先なので、しばらく使われていないと最初の表示に1分ほどかかります。また、公開先が作り直されると、それまでの販売記録は消えます

**触り方**（iPad の Safari を想定しています）

1. 患者さんとして、言語を選び、ほしい薬を伝え、1問ずつ答える
2. 答え終わったら、画面の小さいボタン「薬剤師用：確認の画面を開く」で薬剤師の画面に移る
3. 薬剤師として、まとめ・禁忌の判定・販売手順を見て、薬剤師を選び PIN で承認する
4. 患者さんの画面に戻ると、母国語の説明書と「説明はわかりましたか？」が出る
5. 販売記録の一覧は `/pharmacist/records` で見られます

問診の途中で「胸が痛い」などの緊急の症状を入力すると、問診がその場で止まり、緊急の確認に移ります。

## 課題：言葉が通じないと、市販薬を安全に売れない

日本の薬局・ドラッグストアには、旅行で訪れた方や日本で暮らす外国人の方が市販薬を買いに来ます。けれども、言葉が通じないと次のことが十分にできません。

- **聞き取り**：持病・アレルギー・妊娠・飲んでいる薬など、売ってよいかを決めるための質問
- **説明**：飲み方・注意すること（説明書は日本語だけ）
- **理解の確認**：説明が本当に伝わったか

スマホの翻訳アプリで乗り切ろうとしても、聞き漏れや誤解が残ります。その結果、「安全に売れるか確かめられないので売れない」「時間がかかりすぎる」ということが起きています。多言語を話せるスタッフがいない店では、なおさらです。

薬局薬剤師として、この「聞き取れない・説明できない・伝わったか確かめられない」を店頭で何度も感じてきました。言葉が通じなくても、薬剤師がいつもの手順のまま安全に対応できるようにする。これが MODA の出発点です。その先に、外国人の方が日本で医療を受けやすくなることを目指しています。

## 解決策：1台の iPad で、母国語の問診から販売記録まで決まった順番で進める

患者さんと薬剤師が一緒に1台の iPad を使い、次の流れで進めます。

1. **患者さんが母国語を選ぶ**（9言語：日本語・英語・中国語〔簡体・繁体〕・韓国語・スペイン語・ポルトガル語・フランス語・ベトナム語）
2. **ほしい薬を伝える**（商品名・成分名の入力か、スマホの画面や箱の写真。ほしい薬がなければ症状から探す）
3. **体の状態や症状に、母国語で1問ずつ答える**（次に聞く質問はサーバーが決める。男性には妊娠・授乳を聞かない）
4. **緊急症状があれば、その場で問診を止める**。薬剤師が根拠を確かめてから、母国語で 119番と受診を案内する
5. **薬剤師の画面**に、日本語のまとめ・薬の候補・禁忌の判定・区分ごとの販売手順のチェックリストを出す（候補は薬剤師にだけ見せる）
6. **薬剤師が PIN で承認する**。市販薬で対応できなければ、受診をすすめる案内を出す
7. **母国語の説明書（日本語の原文も併記）**を表示・印刷し、理解できたかを確かめる
8. **患者さんの評価**をもらい、**販売記録**を残す

問診の決まった質問のほかに、患者さんと薬剤師が自由に入力した文を AI で訳し合う欄もあります。訳は「参考訳」と表示し、薬剤師の画面には、AI の訳を日本語に訳し戻した文も並べて、訳の正しさを確かめられるようにしています。

1〜8 の流れは、すべてハッカソンの期間中に作りました（[`docs/spec.md` のタスク分解](docs/spec.md)）。

## 安全の考え方

医療にかかわるアプリなので、「便利さ」より先に「止めるべきところで必ず止まる」ことを優先しています。

| 考え方 | どう守っているか |
| --- | --- |
| **AI は助言しない。判断は薬剤師** | AI が手伝うのは、問診の聞き取りと翻訳だけです。薬の候補・禁忌の判定・説明の文は、すべて**薬剤師への提案**として出し、販売してよいかは薬剤師が決めます。患者さんの画面に、AI が薬をすすめる表示は出しません |
| **AI の出力をそのまま使わない** | AI の答えは、決められた形かをサーバーで確かめ、安全のチェックをかけてから使います。AI の訳には「AI が翻訳したもの（まだ人が確認していない）」ことを画面に表示します |
| **禁忌の薬は、はじめから選べない** | 持病・妊娠・年齢などから禁忌に当たる薬は、薬剤師の画面でも既定で選べません。解除には薬剤師の PIN の再入力と理由の記録が必要です |
| **緊急症状は、問診を止めて薬剤師が確認する** | 緊急のキーワードが入力されるか、薬剤師が「緊急の確認を開く」を押すと、問診はすぐに止まり、患者さんには母国語で「スタッフがすぐにお手伝いします」と出ます。119番の案内は、薬剤師が根拠を確かめてから出します（むやみに救急を使わないため）。この確認と案内は、通信が止まっていても出せます |
| **承認の前は、販売に進めない** | 説明書の印刷・服薬指導・会計の案内は、サーバー側で「薬剤師の承認が済んでいるか」を必ず確かめます。画面の表示だけで止めているのではありません |
| **区分ごとの販売手順を守る** | 要指導医薬品・第1類・指定濫用防止医薬品など、区分ごとの手順と数量の基準をデータ（施行日つきの版）で持ち、未完了の手順があれば先に進めません |
| **販売記録は上書きしない** | 承認と同時に販売記録を作り、理解の確認などの結果は新しい版として足していきます |
| **個人情報を持たない** | 患者さんの氏名は聞きません。問診の内容や健康の情報はログに出しません |

ルールの正しさは、薬剤師が1行ずつ確認した表（[`docs/demo-data/`](docs/demo-data/README.md)）からテストを作って確かめています。表にないケースを、開発の都合で「正解」にすることはしません。

## Claude との作り方

コードを読む経験の少ない薬剤師が、Claude Code に作ってもらいました。安全にかかわるアプリなので、次のように進めました。

- **守るルールを先に書く**：「承認の前は販売に進めない」「緊急症状はすぐに問診を止める」など、どんな指示でも緩めないルールを、Claude が毎回読む指示書（[`CLAUDE.md`](CLAUDE.md)）に書きました
- **正解は薬剤師が決める**：禁忌判定・販売手順・緊急症状の表は薬剤師が1行ずつ確認し、テストはその表からだけ作ります。表にないことは、Claude が判断せずに質問します
- **安全にかかわる変更は、別のモデルがレビューする**：作るモデル（Claude Opus 5.5）とは別のモデル（Claude Fable 5.1）に、禁忌・承認・緊急・販売記録にかかわる変更と、公開前の点検をさせました
- **1回の作業は1つのタスク**：タスクごとにプルリクエストを作り、何を変えたか・なぜか・どう確かめるかを日本語で報告させました
- **簡略化したところは一覧に残す**：ハッカソン版で省いたことや保留にした判断は、改修候補の一覧（[`docs/backlog.md`](docs/backlog.md)）に残しました

## 動かし方

Node.js 22 以上と pnpm が必要です。

```bash
pnpm install
```

```bash
pnpm dev
```

http://localhost:3000 を開くと、言語を選ぶ画面が出ます（iPad の Safari で使う前提の画面です）。

デモを最後まで通すときは、1台のサーバーで動かします（ハッカソン版は接客の記録をサーバーのメモリに置いているため。[`docs/backlog.md` の S-03](docs/backlog.md)）。

```bash
pnpm build
```

```bash
pnpm --filter @moda/web start
```

テスト・型チェック・書き方のチェックは、まとめて次で実行できます。

```bash
pnpm check
```

- 薬剤師の承認には PIN の設定が要ります。`.env.example` を見本に `apps/web/.env.local` を作り、`MODA_PHARMACIST_PINS` を入れてください。
- AI は、開発中は「仮の AI」で動きます。本物の AI（Claude API）を使うときは、`.env.example` を見本に `.env.local` を作り、サーバー側だけにキーを置きます（`.env.local` はコミットしません）。
- 開発する人向けの準備と作業の流れは [`docs/setup.md`](docs/setup.md)、公開 URL の作り方（Render）は [`docs/deploy-render.md`](docs/deploy-render.md)、iPad の実機での確かめ方は [`docs/ipad-check.md`](docs/ipad-check.md) にあります。

## 今後の計画

ハッカソンのあと、薬局2店舗で試験運用し、その後は外国人対応に慣れていない個人・中小の薬局やドラッグストアにも使ってもらうことを目指します。

**試験運用で測ること**：やり取りに齟齬や不足がないか（患者さん・薬剤師の評価）、1件の接客時間、販売できた件数・断った件数（導入前の実測と比べる）。

**試験運用までに直すこと**（主なもの。全体は [`docs/backlog.md`](docs/backlog.md)）

- 9言語の定型文（緊急案内・注意文・用法の型）を、外部で人が確認する（いまは AI の訳のまま。S-07）
- 架空の薬のデータを、実際の取扱薬の添付文書から作り直して薬剤師が確認する（S-08）
- 接客の記録をデータベースに保存し、販売記録を版で残す（S-03）
- 薬剤師のログイン・PIN、店舗ごとの分離（S-09）
- 緊急の記録を、通信が止まっても端末に一時保管できるようにする（S-04）
- AI の接続先を国内で処理するサービスに切り替える（AI の呼び出し口1か所の差し替え）

**ハッカソン版には入れず、そのあとで考えるもの**：音声での問診、母国の処方箋や薬の箱の読み取り（行政への確認が取れてから）、取扱薬を店舗が登録する管理画面、受診案内に店舗が登録した近くの病院を出す機能。
